# 実物の定義

hymme の実物は、このリポジトリをプラグインとして読み込んだ Claude Code のセッションです。hook が実際の道具の呼び出しを止めるかどうかは、テストの中で hook を呼ぶだけでは確かめられません。

## 起動

- 触る面: Claude Code のセッションの中で動く hook(`hooks/hymme_hook.py` と、既存の3本の検査)
- 起動のコマンド: `claude -p "<入力>" --plugin-dir <このリポジトリ> --settings '{"enabledPlugins":{"hymme@hymme":false}}'`
- 前提: Claude Code(`claude`)が入っていること。インストール済みの hymme は設定で切り、作業ツリーの版だけを読ませる。`loopeng/bin` を PATH の先頭に足す
- 準備ができた合図: セッションが入力に返答する(待つ対象のサーバーは無い)
- 並べて動かせるか: できる。確かめに使うリポジトリは一時ディレクトリに作るので、互いに干渉しない

## 健全性の確認

`claude --version` が版を返すこと。返らなければ、確かめは始めない。

## 操作

確かめる機能は「作業者の承認が無い検証の入口を止める」です。

- 前提: 一時のリポジトリに、閉じた抽出の台帳と、形の整った確認の一覧(承認は無い)を置く
- 操作: セッションに、検証の入口(`tlc` の直接の実行)を1回実行させる
- 観察できる結果: セッションの返答に「作業者の確認ゲート」の文言が出る。TLC は実行されない

これを1本のスクリプトにまとめてあります(`scripts/real-session.sh`)。

## 証跡

`tasks/evidence/real-session.log`(git 管理外)に、実行の時刻、確かめたコミット、セッションの返答の全文を残す。

## 後片付け

一時のリポジトリは、スクリプトが終わるときに消す。セッションは1回の入力で終わるので、止めるプロセスは無い。証跡のファイルは消さない。

- 確認のコマンド: `bash scripts/real-session.sh`
- 検証と本番で違う値: モデルは確かめでは haiku、普段のセッションでは作業者の設定のモデル。hook はモデルに依存しないので、結果には効かない。確かめのセッションはインストール済みの hymme を切っているが、普段は切らない。作業ツリーの版とインストール済みの版が違うあいだは、普段のセッションに古い版の検査が掛かる
