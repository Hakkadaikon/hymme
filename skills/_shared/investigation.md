# 読み取りだけの調査

「どう動いているか」「なぜこうなっているか」「どちらを選ぶべきか」を問われたときの決まり。調査はコードを変えない。成果物は、引用を付けた説明か、勧めである。

## 手順

1. **問いが指すコードをたどる。** 理由を問われたら、git の履歴と PR の議論も読む。
2. **答えを次の形で書く。**
   - 仕組みの問い: 概要、主要な概念、動き方、どこに何があるか、注意点。
   - 選択の問い: 案ごとの得失の表と、勧め。
3. **主張ごとに根拠を付ける。** コードなら `ファイルパス:行番号`、履歴ならコミットや PR。確かめていないことは、確かめたことと分けて書く。
4. **「本当にそうか」と問われたら、自分の判断を理由と一緒に書く。** 問いの前提が誤っていれば、そう伝える。
5. **調査の中で直さない。** コミットも PR も作らない。調査がコードの変更の前段なら、結果を返してから通常の工程へ渡す。バグは escape-flow、機能は superpowers:brainstorming、構造の変更は refactor-flow。

## 委任するとき

広く探す調査は、組み込みの `Explore` に委任する。依頼文には、問い、上の答えの形、主張ごとに根拠を付けることを書く。期待する結論は書かない。委任するかの判断は [`parallel-delegation.md`](parallel-delegation.md) に従う。
