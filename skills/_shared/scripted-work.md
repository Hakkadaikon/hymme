# 手作業の代わりにスクリプトを作る

同じ操作を多くの対象に当てる作業と、結果を数えたり比べたりして出す作業は、手で行わない。その作業を行うスクリプトか、結果を確かめるスクリプトを作る。置き換え、移行、集計、点検が当たる。

作るかどうかは、対象の数ではなく、手で行って誤る余地があるかで決める。1か所だけの移行でも、手順が込み入っていて結果を目で確かめきれないなら、スクリプトにする。手で行ってよいのは、2〜3か所の明らかな編集だけである。

次は対象にしない。

- 設計とテストから書く実装の編集。確かめるスクリプトの役は、テストが果たす。
- コードを読んで答える調査([`investigation.md`](investigation.md))。件数や一覧を答えに含めるときだけ、それを出したコマンドを添える。

スクリプトは毎回同じ結果を返し、レビューする人が再実行して確かめられる。手作業の結果は、どちらもできない。

## 作り方

1. 最初の1件を手で行う。
2. その作業を行う(または結果を確かめる)スクリプトを書く。
3. 最初の1件にスクリプトを当て、手で行った結果と同じになることを確かめる。編集なら、手で直した変更を元に戻してから当てる。
4. 残りの全体に当てる。

## 守ること

- 何回実行しても同じ結果になるように書く。
- 目的を果たす最小のスクリプトにする。汎用の枠組みは作らない。
- スクリプトを、レビューする人が再実行できる形で残す。作業がこのセッションで終わらないなら、ファイルにしてコミットする。1回で終わる作業なら、PR の本文かコミットメッセージに全文を載せる。
- 置き換えのスクリプト、生成のスクリプト、点検のコマンド、subagent に読ませる手順の文書のどれも残っていなければ、この決まりに従ったことにならない。
- 同じ作業を複数の subagent に配るより、決定的なスクリプト1本を選ぶ。それでも配るときの決まりは [`parallel-delegation.md`](parallel-delegation.md) の「委任するかを先に決める」に従う。
