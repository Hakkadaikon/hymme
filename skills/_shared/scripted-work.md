# 手作業の代わりにスクリプトを作る

些細でない作業は、手で行わず、その作業を行うスクリプトか、結果を確かめるスクリプトを作る。編集、移行、分析、点検のどれにも当てはまる。作るかどうかは、繰り返しの回数ではなく、些細かどうかで決める。手で行ってよいのは、2〜3か所の明らかな編集だけである。

スクリプトは毎回同じ結果を返し、レビューする人が再実行して確かめられる。手作業の結果は、どちらもできない。

## 作り方

1. 最初の1件を手で行う。
2. その作業を行う(または結果を確かめる)スクリプトを書く。
3. 最初の1件にスクリプトを当て、手で行った結果と同じになることを確かめる。編集なら、手で直した変更を元に戻してから当てる。
4. 残りの全体に当てる。

## 守ること

- 何回実行しても同じ結果になるように書く。
- 目的を果たす最小のスクリプトにする。汎用の枠組みは作らない。
- スクリプトをファイルとして残す。置き換えのスクリプト、生成のスクリプト、点検のコマンド、subagent に読ませる手順の文書のどれも残っていなければ、この決まりに従ったことにならない。
- 作業がこのセッションで終わらないなら、スクリプトをコミットする。1回で終わる作業なら、PR の本文かコミットメッセージに載せ、レビューする人が再実行できるようにする。
- 同じ作業を複数の subagent に配るより、決定的なスクリプト1本を選ぶ。それでも配るときの決まりは [`parallel-delegation.md`](parallel-delegation.md) の「委任するかを先に決める」に従う。
