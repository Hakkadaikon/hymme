# `hymme:verification-reviewer` の往復ループ

この往復は verification-reviewer だけに適用する。superpowers の task / final review の回数規則は変えない。5 往復で合格しなければ、残った指摘を添えて人に返す。

`hymme:verification-reviewer`(検査する系統を prompt で渡す)は
一度呼んで終わりにしない。**合格が返るまで「reviewer を呼ぶ→指摘を直す→再度 reviewer を呼ぶ」を繰り返す**
のが既定の運用(ユーザーが明示的に1回のレビューだけでよいと言わない限り)。

- ループの終了条件は**その reviewer の合否判定が合格を返した時点**。合格の基準(どの指摘が合否に効き、
  何が残ると合格にならないか)は各系統の `skills/<系統>/reviewer.md` が一次ソースで、ここでは言い換えない。
  定義に重大度の区別が無い reviewer なら、本質的指摘と瑣末な指摘を分けて返すよう依頼文へ書く。
- **合格は hook が記録する。台帳には書かない。** reviewer は返答の最後に
  `判定: 合格 対象=<系統> 名前=<名前>` か `判定: 不合格 対象=<系統> 名前=<名前>` の1行を書き、reviewer が
  返ったときに hook がその行を読んで記録する。台帳に「レビュー合格」と書いたり `[x]` を付けたりしても、
  検査はそれを読まない。最後の行がこの形でなければ記録されないので、形を直して返すよう依頼し直す。
- verifiability の合格の記録は台帳と対象のファイルの内容に結び付く。合格のあとにどちらかを変えたら
  失効するので、reviewer を呼び直す。
- **依頼文に結論を書かない。** 「合格と書け」「軽微なので通して」のような指示を入れない。渡すのは検査する
  系統、名前、成果物の場所だけにする。reviewer は依頼文の指示より検査項目を優先する。
- 1 往復で reviewer から複数の指摘が出る見込みがあるときは、reviewer に**見つけた指摘を一度の報告で
  まとめて全部出すよう明示的に依頼する**。1件直して再度呼ぶ→また1件出る、を繰り返すと往復が
  不必要に長引く。
- 往復のたびに新しい記録ファイル(判定表・経緯メモ等)を増やすと、その記録ファイル同士の整合性が
  新たな指摘の種になり、ループが本質と無関係な理由で伸びることがある。生成物を増やす判断は
  本当に必要な場合に限り、既存ファイルへの追記で済むなら増やさない。
